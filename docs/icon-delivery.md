# Icon delivery and release size

Material Icons and Material Symbols in server-driven UI are fetched **as SVG vectors** on demand from Google's static `fonts.gstatic.com` CDN. `SvgIcon` constructs a URL from the icon model's family, style, name and (for Material Icons) catalog version, then uses `SvgPicture.network` with a tint `ColorFilter`. This applies to icons in buttons, navigation, text fields and other SDK widgets because they all use `retrieveIconWidget` / `SvgIcon`. No PNG generation or custom `ImageProvider` is needed: `ImageProvider` decodes to raster `ui.Image`, whereas `flutter_svg` parses and draws vectors. The editor's icon picker uses the same widget.

The previous `material_icons_by_name.dart` enumerated ~8,800 `Icons.*` constants. A reachable map of every font glyph prevents MaterialIcons font tree shaking even when an app uses one icon. It is removed. Constructing `IconData` from serialized codepoints at runtime is not an alternative: Flutter's release icon tree shaker rejects nonconstant `IconData`, and Google's codepoints differ from Flutter's. The old PNG/export experiment (`material_icons/`) is unrelated to runtime rendering and should not be bundled into SDK apps.

Material SVGs are color-filtered so their tint, sizing and themed defaults still work; Symbols retain snapped weight/grade/fill/optical-size variants. The SVGs and their URLs are served by Google with cross-origin access and cache headers (Material Icons: one year for tested versions; Symbols: one day for tested variants). Apps need network access on first use; failed loads leave the icon's space empty. An application CSP or an enterprise firewall must permit `https://fonts.gstatic.com`. For an offline or first-party-hosting requirement, mirror the same immutable SVG URL paths to a CDN (e.g. Cloudflare R2/Workers or Firebase Storage) and make the URL base configurable, with manifest/version validation and HTTP cache headers; a proxy service in the rendering path adds latency and availability risk and is unnecessary for the current hosted delivery.

Cupertino is distinct: its serialized models carry font codepoints rather than names. The SDK builds immutable SVG URLs at `https://icons.codelessly.com/cupertino/1.0.9/<lowercase-hex-codepoint>.svg` and renders them with `SvgPicture.network` using the same size/tint behavior as the previous font widget. The 1,234 SVGs are exported from `cupertino_icons` 1.0.9 by `tool/export_cupertino_svg.py` and hosted on a static Cloudflare R2 custom domain, with `image/svg+xml`, `Access-Control-Allow-Origin: *`, and `Cache-Control: public, max-age=31536000, immutable`. A versioned [manifest](https://icons.codelessly.com/cupertino/1.0.9/manifest.json) and [upstream license](https://icons.codelessly.com/cupertino/1.0.9/LICENSE) accompany the SVGs. Override the CDN root with `--dart-define=CODELESSLY_CUPERTINO_SVG_BASE_URL=https://your-host` if you mirror the corpus. A CDN/network outage leaves the icon's space empty; an app CSP must allow `https://icons.codelessly.com`. There is no runtime font fallback, because referencing the 1,234-entry `IconData` map prevents Flutter's release font tree shaking. That source map remains only as an exporter reference, and is no longer exported in the SDK barrel (a public API change for consumers importing `cupertinoIconsByCodepoint`). The other legacy name/codepoint maps (`flutter_icons_names_map.dart`, `flutter_icons_data_map.dart`) remain public SDK APIs used for editor/code-generation interoperability; they are not used by the Material icon renderer. Avoid making them reachable from runtime rendering. Generated source size is not itself the same as release artifact size. In matched release probes on the same Flutter toolchain (November 2026), removing the Material map reduced the **web MaterialIcons font from 1,261,012 to 10,012 bytes** (−1,251,000 bytes); `main.dart.js` was byte-identical at 3,346,451 bytes. The Android APK was also byte-identical at 50,934,073 bytes (Android already reduced that font to 2,616 bytes). The empty probe produced a 43,143,664-byte APK and a 1,736,925-byte web `main.dart.js`; SDK overhead on these probes is therefore 7,790,409 APK bytes and 1,609,526 uncompressed JS bytes, plus the remaining fonts/assets. SDK web CupertinoIcons remained 209,160 bytes (empty app: 1,472). With the verified Cupertino CDN and map export removed, the same web probe's Cupertino font shrank from 209,160 to **1,472 bytes** (−207,688 bytes), matching the empty app, while `main.dart.js` became 3,359,052 bytes. The earlier probe was `MaterialApp(home: Scaffold(body: Center(child: CodelesslyWidget(layoutID: 'size-probe'))))` versus the same app with `Text('Size probe')`, built with `flutter build web --release --no-pub` and `flutter build apk --release --no-pub`. The post-Cupertino run used the same probe pointing at the current SDK. The Android APK built successfully at 50,934,169 bytes; this probe app itself depends on `cupertino_icons`, so Android still packages its complete 257,628-byte font (115,944 compressed bytes), and the SDK's SVG migration does not claim an Android APK-size reduction. Removing an app-level font dependency requires a separate app migration. These numbers describe minimal probes, not a production app, and are sensitive to target and Flutter version.

## Other measurable contributors / follow-ups

* The earlier SDK probe added 1,609,526 bytes to web `main.dart.js` (409,790 gzip bytes); deleting the Material glyph map did **not** reduce this JS. Migrating Cupertino to first-party SVGs removed the remaining 207,688-byte web font overhead, while keeping an empty 1,472-byte font asset for Flutter's own Cupertino icon references. The post-migration JS measurement above uses a freshly resolved current SDK and should not be treated as a byte-for-byte before/after JS comparison against the earlier baseline.
* The SDK APK adds 7,790,409 bytes: ~2,586,912 more compressed `classes.dex` bytes and ~3,997,696 more bytes of `libapp.so` across **three** ABIs. The Flutter engine copies are unchanged. Splitting native features (Firebase, payments, media/webview) into opt-in packages is the most promising but needs API/feature migration and separate build measurements. Release AAB or per-ABI builds also avoid delivering all three ABI copies to each device.
* Web output includes ~602 KB of CodelesslyAPI schema JSON assets, ~89 KB SDK logo PNG, and ~118 KB additional notices. Measure actual runtime schema use before pruning package assets. Legacy SDK source maps `flutter_icons_names_map.dart` (~406 KB) and `flutter_icons_data_map.dart` (~289 KB) have no demonstrated contribution to this release JS/APK probe; moving them to editor-only packages is a source/publish-size improvement with public-API compatibility costs, not a measured binary win.
