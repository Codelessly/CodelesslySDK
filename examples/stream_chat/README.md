# Generative UI chat

A minimal chat whose replies carry inline UI: each reply is a `UiSession` shown by `CodelesslyView`, filling in as
the model's `ui_apply` tool call streams. Tapping in the UI (choosing a flight, confirming) is the user's next turn;
a follow-up ("Sort them by price.", "Make it dark.") edits the same UI with a few ops instead of regenerating it,
and the reply says how many output tokens that took.

```sh
flutter run                                                   # recorded streams, offline
flutter run --dart-define=ANTHROPIC_API_KEY=<key> \
            --dart-define=MODEL=claude-sonnet-5-5              # live (default model: claude-haiku-5-5)
flutter test                                                  # the chat over recorded streams; the live request, offline
```

| File | |
|---|---|
| `lib/main.dart` | The chat screen. |
| `lib/src/sources.dart` | `StreamSource`, `RecordedStreamSource` (plays `assets/streams/*.jsonl` at their recorded pace), `LlmStreamSource` (live). |
| `lib/src/llm.dart` | The live request (pure Dart, shared with the record command): Anthropic's Messages API through `anthropic_sdk_dart`, the two tools with `eager_input_streaming` so the tool input arrives as it is generated, the `input_json_delta` text of the `ui_apply` call fed straight to `UiSession.applyStream`; the demo briefs. |
| `assets/system_prompt.md` | The system prompt sent (generated by `dart run tool/system_prompt.dart`: the op rules, the node and action types the agent profile allows, and codelessly_api's generated STARTER). 60,181 characters, about 15,000 tokens by the 4-characters-per-token estimate (the record command counts it with the API when run). Sent with prompt caching. |
| `tool/record.dart` | Records one real generation in the replay format. |

Supported models (`MODEL`, `--model`): `claude-haiku-5-5` (default: fast inline answers; thinking off),
`claude-sonnet-5-5` (thinking between tools only), `claude-opus-5-5` and `claude-fable-5-2` (adaptive thinking;
it cannot be turned off on them). Effort is low for all: a UI answer is mostly output.

## Recording a real stream

```sh
ANTHROPIC_API_KEY=<key> dart run tool/record.dart --ui flights --model claude-haiku-5-5 \
    --out ../../tool/stream/streams/live/flights@claude-haiku-5-5.jsonl --followup
../../tool/stream/replay.sh ../../tool/stream/streams/live/flights@claude-haiku-5-5.jsonl --out ../../tool/stream/out/live-flights-haiku
```

`--ui` is one of `flights`, `weather`, `restaurant_menu`, `saas_pricing` (generic briefs in `lib/src/llm.dart`;
`--prompt` replaces the brief). It saves the exact `ui_apply` input deltas with their arrival times
(`{"tMs", "delta"}` lines after a `{"meta"}` line with usage: input and output tokens, cache reads, time to first
token, to the first tool delta and in total, the stop reason, and how the ops fared under strict validation). When
ops were rejected or children never arrived, it sends the diagnostics back once as the tool result and records
the retry (`.retry.jsonl`); with `--followup` it then sends the brief's follow-up edit and records it
(`.followup.jsonl`). The key is read from the environment only: nothing writes it, and the files hold no request
headers. Without the key the command exits with status 2 and says so.

**Untested against a live endpoint**: in the environment this was built in, the run could not be authorized, so
the live source and the record command were checked only offline (the request JSON, the missing-key exit). Run
the two commands above to record real streams; the replay command plays them like the synthetic ones.
